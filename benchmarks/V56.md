# v56: pseudo-legal search performance

The initial uploaded `.sb3`, v55 and v56 are measured in the **actual TurboWarp compiler**, with three warm-compiler samples per case. The original upload is preserved in `baseline/TurboKnight-5-v52.sb3`. Both report files include the exact release checksums.

## Real GUI, 0.5-second thinking time

These runs include the original graphics, question prompt, mouse input, real broadcasts and controller delivery. Opening books are cleared and all three variants use 50,000 TT buckets (200,000 entries). This normalizes the original compiled configuration’s much larger table. Wall time includes mouse interaction and reply delivery; it is not purely search time.

| Version | Median raw nodes/s | Median distinct positions/s | Completed depths in three samples |
| --- | ---: | ---: | --- |
| Original v52 | 150,509 | 93,835 | 7, 7, 7 |
| v55 | 27,429 | 27,429 | 4, 4, 4 |
| v56 | 81,882 | 81,882 | 9, 9, 9 |

In this run, v56 recovered **2.99× v55’s end-to-end position throughput**, reaching about **87% of the original’s** distinct-position throughput. This is a measured recovery, not a universal speed guarantee. Different trees and the mandatory scalar context stack still have costs.

## Isolated search kernel

| Position / requested depth | v52 median ms | v55 median ms | v56 median ms | v55 generations/raw node | v56 generations/raw node |
| --- | ---: | ---: | ---: | ---: | ---: |
| start / 4 | 7.00 | 62.70 | 20.50 | 2.67 | 0.29 |
| kiwipete / 3 | 49.10 | 625.90 | 60.90 | 8.24 | 0.16 |
| rook-endgame / 4 | 3.40 | 49.70 | 9.20 | 2.88 | 0.31 |

The middlegame slowdown in v55 is reproduced: over eight whole move-generation calls per node. v56 removes full enemy reply-generation probes. Check state comes from the original small king-target ray/knight/pawn lookup; the normal generated moves remain pseudo-legal and the child rejects an illegal predecessor. Quiet quiescence again uses captures/promotions only, with stand-pat before generation. A rare quiet-witness fallback retains stalemate correctness.

## Reading the counters correctly

v52 increments its node count once in negamax and again when the same depth-zero position enters quiescence. v55/v56 count that position once. The reports retain **both** raw counters and distinct position entries, subtracting recorded NEG-to-Q delegations in the original. No release node count has been inflated. At a timed stop boundary the original correction can differ by one entry; completed fixed-depth measurements have no such ambiguity.

Nominal depths are selective, not exhaustive depths. v56 restores the initial logarithmic late-move reduction formula, pseudo-move ordinal and futility margin, while keeping checking-move/promotion safeguards, corrected quiescence and full promotion coverage. The search trees and position counts are therefore different. The fixed-depth table deliberately shows where v56 still takes longer than the initial version; restored generation throughput does not imply identical depth latency.

## Reproduce

```sh
npm ci --ignore-scripts
npx playwright install --with-deps chromium
npm test
npm run benchmark:compiled
npm run benchmark:gui
```

The tests enforce zero generation for a quiet stand-pat cutoff, no full-reply generation from the king-status routines, and at most one normal generation per searched node. GUI regression, stack restoration, perft, legal moves, checks, pins, promotions and terminal positions are also tested. These performance cases are not an Elo test.
